# Blossom 0.2.9.2

Memory-pressure hotfix following a Linux world-entry freeze report. The supplied
kernel log confirms exhausted RAM/swap and OOM kills, but does not identify the
allocating process. This release does not claim a reproduced root-cause leak fix.

- Restore vanilla world-transition garbage collection, including profiles that
  previously enabled skipping it. Remove the skip-GC control.
- Bound Java direct buffers to 512 MiB in both launchers, independently of the
  configured Java heap. This does not cap GPU allocations or total process RAM.
- Automatic chunk workers now max out at two; manual settings remain available.
- Add `BLOSSOM_SAFE_MODE=1` / `-Dblossom.safeMode=true` to bypass all game patches
  before startup. Existing worlds/profiles are preserved.
- Include the unreleased adaptive chunk scheduling, particle culling, lightmap
  upload caching, rounded UI batching, background screenshot encoding, primitive
  translucent sorting and per-worker region-cache storage reuse.
- Detailed benchmarks add asynchronous GPU timestamp intervals and a standalone
  archive comparison script. No measured gameplay FPS gain is claimed.

Java 8 compilation, headless correctness and transformed-class verification are
covered by the build. Linux/Windows package checks run in CI. These checks do not
reproduce the reported desktop freeze or substitute for graphical world testing.

If a freeze recurs, preserve the complete kernel OOM report (including its process
table) and game log; the last 100 journal lines can omit the largest memory user.
See `docs/LINUX-FREEZE-RECOVERY.md` for startup bypass and diagnostic instructions.
